# Rishika Infra website

Marketing site for [rishikainfra.com](https://rishikainfra.com). It is a static
[Astro](https://docs.astro.build) site styled with Tailwind CSS v4 and deployed to
Cloudflare Workers (static assets).

## Getting started

Requires Node.js 22.

```sh
npm ci
cp .env.example .env   # then fill in the values below
npm run dev            # http://localhost:4321
```

| Variable | Used for |
| --- | --- |
| `PUBLIC_WEB3FORMS_ACCESS_KEY` | Contact and demo form submissions (Web3Forms). Without it the form shows an "email us" fallback. |
| `PUBLIC_GA_TRACKING_ID` | Google Analytics, loaded only after the visitor accepts the cookie banner. Leave empty to disable. |

In production these are set as build variables in the Cloudflare dashboard
(Workers & Pages → rishikainfra → Settings → Variables and secrets).

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Local dev server with hot reload |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the built `dist/` locally |
| `npm run check` | Type-check `.astro`, `.ts` and `.tsx` files |
| `npm run check:links` | Fail if any built page links to a missing page or file (run after `build`) |
| `npm run ci` | `check`, `build` and `check:links` in one go, as CI runs them |
| `npm run check:a11y` | Run axe (WCAG 2.1 AA) on every built page; needs `npm run preview` running |
| `npm run check:lighthouse` | Lighthouse CI against `dist/` with the budgets in `lighthouserc.json` |

## Project layout

```text
public/                 Files served as-is: favicon, robots.txt, _headers, videos,
                        and images referenced by absolute URL (social card, logo)
src/
  assets/images/        Site photos and icons, optimised at build time
  components/           Astro components (Navbar, carousels, tabs, ...)
    islands/            React components that need client-side state (ContactForm)
    shared/             Img, SEO, Analytics and other shared pieces
  data/                 Site config
  layouts/Layout.astro  Page shell: <head>, skip link, navbar, footer
  pages/                One file per route
  scripts/              Small browser scripts shared by components (tabs)
  styles/global.css     Tailwind entry point, theme tokens and keyframes
scripts/                Link and accessibility checkers used in CI
```

## Conventions

- **Images:** put photos in `src/assets/images/` and render them with
  `<Img src="/images/..." alt="..." />` from `components/shared/Img.astro`. It
  generates resized WebP files with `srcset`. Pass `sizes` when the image renders
  narrower than half the screen on desktop. Only files that need a fixed public
  URL (social card, logo, video posters) belong in `public/`.
- **JavaScript:** prefer plain Astro components with a small `<script>`. Use a
  React island only when a component needs real client-side state.
- **Colours and fonts:** use the theme tokens defined in `src/styles/global.css`
  (for example `bg-brand-yellow`, `text-brand-ink`) rather than hex values. For
  yellow-family text on a white background use `text-brand-amber`; plain
  `brand-yellow` text is only readable on dark backgrounds. CI fails on contrast
  below WCAG AA.
- **SEO:** every page passes `title` and `description` to `Layout`. Service pages
  also pass `breadcrumbs` and `schema` for structured data.
- **Security headers** live in `public/_headers`; the Content Security Policy is
  generated by Astro from `security.csp` in `astro.config.mjs`. Add any new
  third-party host there.

## Deployment

Pushes to `Local_Develop` and pull requests build automatically in Cloudflare
Workers Builds using `wrangler.jsonc`; each PR gets a preview URL. GitHub Actions
(`.github/workflows/ci.yml`) runs the type check, build and link check on every
pull request, then an accessibility check (axe) and Lighthouse score budgets on the
built site. Lighthouse reports are kept as a downloadable artifact on each run.
